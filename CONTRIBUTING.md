# Contributing / 贡献指南

## English

1. Open or reference an issue that explains the behavior and acceptance criteria.
2. Create a focused branch such as `feat/delivery-attempt-details`.
3. Keep commits reviewable and use Conventional Commits.
4. Run the complete quality gate before opening a pull request.
5. Update architecture, security, API, or changelog content when behavior changes.

```bash
./scripts/check.sh
```

Pull requests should explain the problem, decision, operational impact, security impact, and verification evidence.

## 中文

1. 创建或关联 Issue，说明问题和验收标准。
2. 使用聚焦的功能分支，例如 `feat/delivery-attempt-details`。
3. 保持 Commit 可审查，并使用 Conventional Commits。
4. 创建 Pull Request 前运行完整质量门禁。
5. 行为发生变化时同步更新架构、安全、API 或 Changelog。

Pull Request 需要说明问题、技术决策、运行影响、安全影响和验证证据。
