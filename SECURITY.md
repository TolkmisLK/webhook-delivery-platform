# Security policy / 安全策略

## Supported version / 支持版本

Security fixes are applied to the latest release and the `main` branch.

安全修复仅应用于最新 Release 与 `main` 分支。

## Reporting a vulnerability / 报告安全问题

Do not disclose an exploitable vulnerability, active credential, signing secret, or sensitive payload in a public issue.

请勿在公开 Issue 中披露可利用漏洞、有效凭据、签名密钥或敏感 Payload。

Use GitHub's private vulnerability reporting channel when it is available. Otherwise, contact the repository owner through the public GitHub profile without including secrets in the first message. Include the affected version, impact, minimal reproduction, and suggested mitigation.

优先使用 GitHub Private Vulnerability Reporting。若该入口暂不可用，请通过公开 GitHub Profile 联系仓库所有者，首次消息不要附带密钥；报告应包含受影响版本、影响范围、最小复现和缓解建议。

For non-sensitive hardening suggestions, open a regular issue and remove all credentials and customer data first.

不涉及敏感信息的安全加固建议可以创建普通 Issue，但必须先移除全部凭据与客户数据。
